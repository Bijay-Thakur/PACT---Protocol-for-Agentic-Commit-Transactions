# Phase 1 integration test transition

The five original `test_int_*.py` modules used the Phase 1 anonymous API, caller supplied root grants, synchronous `/commit` execution, and Phase 1 receipt fields. Phase 2 deliberately requires an authenticated principal, a server issued policy grant, a frozen revision digest, and a durable worker. Running the original requests against Phase 2 produces contract errors before their assertions can execute.

The original source is preserved in `backend/tests/legacy_int_*.py`. Pytest does not collect those names. This is an explicit retirement of an incompatible harness, not a skipped or green Phase 1 result. The current integration tests exercise the supported contract:

| Preserved source | Phase 2 verification |
|---|---|
| `legacy_int_acceptance.py` | `test_int_phase2_demo.py` runs all nine scenarios through an authenticated principal; `test_int_phase2_flow.py`, `test_int_phase2_provider_adverse.py`, `test_int_phase2_restoration.py`, `test_int_phase2_operation_identity.py`, and `test_int_phase2_legacy_guarantees.py` check money movement, barrier blocking, uncertain outcomes, restoration, notification ordering, unique operations, and immutable receipts. The old tests 10 and 11 were placeholders; durable recovery and concurrent commit have direct tests now. |
| `legacy_int_api_and_faults.py` | `test_int_phase2_auth.py` checks identity and request replay; `test_int_phase2_policy.py` checks delegation, frozen plans and approvals; `test_int_phase2_planner.py` checks advisory model proposals; `test_int_phase2_legacy_guarantees.py` checks child commit rejection, invalid recovery states, stable provider idempotency on ambiguous retry, and authenticated event history plus SSE. `test_int_phase2_provider_adverse.py` checks 503 after application and response loss. |
| `legacy_int_concurrency.py` | `test_int_phase2_legacy_guarantees.py` checks three concurrent commit requests, one binding decision, one refund, and stale ORM writes. `test_int_phase2_flow.py`, `test_int_phase2_reservations.py`, and `test_int_phase2_operation_identity.py` check competing roots, budget/resource conflicts, and duplicate business operations. |
| `legacy_int_recovery.py` | `test_int_phase2_worker_fencing.py` checks crash windows before and after intent, external application before a lost response, reconciliation replay, lease takeover and stale worker fencing. `test_int_phase2_restoration.py` checks worker death after an inverse call. The CLI crash/recover smoke was also run manually on the disposable test database; its Phase 1 subprocess test is not run as part of the Phase 2 suite. |
| `legacy_int_scenarios.py` | `test_int_phase2_demo.py` runs the nine authenticated scenarios and checks expected states, transaction/effect detail, and prebarrier absence of provider calls. The old test ran each scenario twice; the replacement runs once per test invocation. |

Phase 1 only response fields and exact attempt labels are not compatibility promises. For example, Phase 2 treats a provider 503 as ambiguous and reconciles or retries with a stable provider idempotency key; Phase 1 expected `REJECTED_RETRYABLE`. The Phase 2 checks assert the external outcome and replay safety. Tests for the live browser, Nebius provider and actual Code Council integration remain separately listed in the acceptance matrix.
